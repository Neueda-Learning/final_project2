# Portfolio Manager REST API

## Contract status

[openapi.yaml](openapi.yaml) is the canonical, machine-readable contract. Runtime
documentation is generated by Springdoc:

- Swagger UI: `http://localhost:8000/docs`
- OpenAPI JSON: `http://localhost:8000/v3/api-docs`
- Business API prefix: `/api/v1`

Controllers use request and response records rather than exposing JPA entities.
Bean Validation defines field constraints, and a shared exception handler produces
the standard error shape.

## Common protocol

| Header | Requirement |
|---|---|
| `Content-Type: application/json` | Required for JSON request bodies |
| `Accept: application/json` | Recommended |
| `X-Request-ID` | Optional client trace ID |
| `Idempotency-Key` | Required when creating a transaction |

Financial values are decimal strings. Timestamps use ISO 8601 UTC, dates use
`YYYY-MM-DD`, currencies are three uppercase characters, and asset types are
`STOCK` or `ETF`.

Paginated responses use this shape:

```json
{
  "items": [],
  "page": 1,
  "pageSize": 20,
  "total": 0
}
```

Errors use this shape:

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Request validation failed.",
  "fieldErrors": {
    "quantity": ["must be greater than zero"]
  },
  "requestId": "01J3EXAMPLE"
}
```

Expected status codes include 400 for invalid semantics, 404 for missing or
inaccessible resources, 409 for conflicts, 422 for field validation, 500 for
unexpected failures, and 503 for unavailable dependencies.

## Portfolios

| Method | Path | Purpose |
|---|---|---|
| GET | `/portfolios` | List portfolios |
| POST | `/portfolios` | Create a portfolio |
| GET | `/portfolios/{portfolioId}` | Get portfolio details |
| PATCH | `/portfolios/{portfolioId}` | Update portfolio metadata |
| DELETE | `/portfolios/{portfolioId}` | Delete a portfolio with no trades |
| POST | `/portfolios/{portfolioId}/archive` | Archive a portfolio |

Portfolio names are unique per active user, case-insensitively. Archived portfolios
are excluded by default.

## Trading

| Method | Path | Purpose |
|---|---|---|
| GET | `/instruments` | Search active stocks and ETFs |
| POST | `/portfolios/{portfolioId}/transactions` | Record a purchase or sale |
| GET | `/portfolios/{portfolioId}/transactions` | List transaction history |
| GET | `/portfolios/{portfolioId}/positions` | List current positions |

Trade creation is atomic and idempotent. A sale cannot exceed the current position.

## Market data

| Method | Path | Purpose |
|---|---|---|
| POST | `/market-data/sync` | Start market-data synchronization |
| GET | `/market-data/sync-runs/latest` | Get the latest synchronization status |
| GET | `/market-data/instruments/{instrumentId}/latest-price` | Get the latest close |

## Analytics

| Method | Path | Purpose |
|---|---|---|
| GET | `/portfolios/{portfolioId}/dashboard` | Get summary, valued positions, and allocation |
| GET | `/portfolios/{portfolioId}/performance` | Get daily valuation history |

Dashboard totals exclude unpriced holdings and report their status explicitly.

## Health

| Method | Path | Purpose |
|---|---|---|
| GET | `/health/live` | Confirm that the API process is alive |
| GET | `/health/ready` | Confirm that the API and MySQL are ready |

## Contract completion criteria

- Every operation has a unique `operationId`.
- Every request body and success response has a schema and example.
- Every business operation documents at least one standard error response.
- All `$ref` values resolve.
- Runtime OpenAPI and the repository contract have no unapproved differences.
