# Portfolio Manager REST API Reference

## 1. Document Status

This document defines the REST API contract implemented by the Spring Boot application and consumed by the frontend.

- OpenAPI specification: [openapi.yaml](openapi.yaml)
- Swagger UI: `GET /docs`
- OpenAPI JSON: `GET /v3/api-docs`
- Local base URL: `http://localhost:8000`
- Business API prefix: `/api/v1`

## 2. Interface Ownership

| Tag | Owner | Scope |
|---|---|---|
| Portfolios | Member 2 | User context, portfolio CRUD/archive |
| Trading | Member 3 | Instrument search, executable prices, transactions, positions |
| Market Data | Member 4 | Synchronization, run status, latest and historical prices |
| Analytics | Member 5 | Dashboard and performance |
| Health | Member 5 | Liveness and readiness |

Member 1 consumes these interfaces and owns the complete frontend.

Route implementation requirements:

- Use Java records as request/response DTOs; never expose JPA entities directly.
- Declare field constraints using `@Valid` and Bean Validation.
- Add semantics and examples with `@Operation`, `@ApiResponse`, `@Schema`, and `@ExampleObject`.
- Emit the standard error body through `@RestControllerAdvice`.
- Include successful and error responses in `/v3/api-docs`.

Runtime documentation is generated by Springdoc. Repository [openapi.yaml](openapi.yaml) is the authoritative review and frontend type-generation contract.

## 4. Common Protocol

### 4.1 Request Headers

| Header | Required | Description |
|---|---|---|
| `Content-Type: application/json` | For JSON bodies | Request media type |
| `Accept: application/json` | Recommended | Response media type |
| `X-Request-ID` | No | Client trace ID; generated by the server when absent |
| `Idempotency-Key` | For transaction creation | Reuse the same value for network retries |

The MVP uses a server-side demonstration user and never accepts an arbitrary user ID from a client header or body.

### 4.2 Data Formats

| Data | JSON format | Example |
|---|---|---|
| UUID | string | `"22222222-2222-2222-2222-222222222222"` |
| Amount/price/quantity/percentage | decimal string | `"1250.00000000"` |
| Timestamp | ISO 8601 UTC | `"2026-07-27T20:00:00Z"` |
| Trading date | `YYYY-MM-DD` | `"2026-07-24"` |
| Currency | Three uppercase characters | `"USD"` |
| Stock/ETF type | enum | `"STOCK"` / `"ETF"` |

Financial numbers are strings to prevent JSON binary floating-point precision loss.

### 4.3 Paginated Response

```json
{
  "items": [],
  "page": 1,
  "pageSize": 20,
  "total": 0
}
```

### 4.4 Standard Error Response

### 6.3 Create a Buy or Sell Transaction

`POST /api/v1/portfolios/{portfolioId}/transactions`

The client selects an exact UTC `executionTimestamp` from the instrument's stored
one-minute bars. The server loads that bar, uses its close as the immutable
execution price, and derives currency from the bar. Seconds and fractional
seconds must be zero. `unitPrice` and `currency` cannot be supplied by the client.

```bash
curl -s -X POST \
  "http://localhost:8000/api/v1/portfolios/22222222-2222-2222-2222-222222222222/transactions" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: demo-buy-aapl-001" \
  -d '{
    "instrumentId": "33333333-3333-3333-3333-333333333333",
    "side": "BUY",
    "quantity": "10.00000000",
    "executionTimestamp": "2026-07-27T19:59:00",
    "feeAmount": "0.00000000",
    "note": "Initial position"
  }'
```

## 10. OpenAPI Completion Criteria

- [openapi.yaml](openapi.yaml) parses successfully as YAML.
- Every endpoint has a unique `operationId`.
- Every request body and success response has a schema and example.
- Every business interface defines at least one standard error response.
- A 204 response declares no JSON body.
- Every `$ref` resolves into `components/schemas`.
- Runtime `/v3/api-docs` has no unapproved differences from the repository specification.
- Frontend types are generated from the specification or compatibility-checked in CI.
