Architectural Diagram

Production-Oriented Architecture

Two parallel data paths: synchronous user requests (blue/teal) flow through Frontend → API → Database and back; asynchronous market refresh (green) runs independently via Worker → Market Data → Database. CI validates all releases continuously.

User request path Async refresh path External integration Quality assurance
acceptors · architecture
Our architecture has two distinct data paths. The primary path handles user requests: trades and portfolio queries flow from the React frontend through the Spring Boot backend to MySQL, with responses flowing back. This path is synchronous and optimized for responsiveness. The secondary path handles market data refresh: a background worker scheduler periodically requests the latest quotes from external market data providers and persists them to the database. The separation means user-facing operations never block on external API latency, and market data updates are decoupled from trading actions. CI continuously validates that both paths work together correctly. Each layer has clear responsibilities, making the system easier to debug, extend, and operate.

Conclusion

What We Achieved and What We Learned

Delivered Outcomes

  • Portfolio lifecycle workflow implemented end-to-end.
  • Market synchronization and valuation integrated.
  • Demonstrable user-facing analytics dashboard.

Challenges We Faced

  • Cross-layer integration timing and contract drift risk.
  • Environment consistency in non-container startup paths.
  • Balancing rapid iteration with reliability safeguards.

Team Reflection

We collaborated effectively through ownership clarity, shared checkpoints, and disciplined integration feedback loops.

What We Would Do Differently

Introduce stricter contract tests earlier and establish environment templates at the very beginning of development.

acceptors · conclusion
Now let's take a moment to reflect on what we actually delivered, and what this project taught us. On the delivery side, we implemented the complete portfolio lifecycle from end to end — users can create portfolios, record trades, and immediately see how those actions flow through to their analytics dashboard. Market data synchronization is fully integrated, meaning valuation figures reflect real pricing rather than static placeholders. And the entire experience is demonstrable in a live environment, which was always our goal from day one. That said, we did face real challenges along the way. The most significant one was cross-layer integration — keeping the frontend, the API, and the worker in sync as each module evolved independently. We also ran into environment consistency issues: getting everyone's local setup to behave identically required more coordination than we initially anticipated. And throughout the project, we were constantly balancing the speed of iteration against the need for reliability safeguards. As a team, what made us effective was ownership clarity. Each member had a well-defined module, which meant decisions could be made quickly and accountability was always clear. Our shared checkpoints kept integration on track without slowing individual progress. If we did this again, we would introduce stricter contract tests between layers much earlier — and we would establish shared environment templates from the very first day, rather than letting those gaps surface mid-project.

acceptors · next phase
Looking forward, our priorities are focused on optimization — not adding features, but making what we have more reliable, more observable, and more production-ready. First, on reliability: we want to strengthen startup consistency and build proper operational runbooks, so the system is easier to hand off and recover from failure without depending on tribal knowledge. Second, on quality depth: we plan to expand our regression coverage, introduce stronger contract-level checks between our layers, and improve the observability signals that help us detect issues earlier. Third, on product hardening: we want to establish a disciplined release checklist that brings the system closer to genuine production readiness — not just demo readiness. We landed all five core modules. The architecture is clean, the contracts are clear. What comes next is about making this system easier to operate, easier to validate, and safer to evolve over time.
