acceptors · project story
Before introducing the system, let's first look at the problem we wanted to solve. Many investors manage their portfolios using multiple spreadsheets, brokerage platforms, or different applications. As a result, portfolio records become fragmented, making it difficult to get a complete picture of their investments. Another common challenge is that profit and loss tracking is often done manually. This process is not only time-consuming but also prone to errors and delays. Without a unified view of their holdings, users may struggle to make timely investment decisions. To address these problems, we developed a Portfolio Manager that brings everything together in one platform. Users can manage their portfolios, view the entire trade lifecycle, monitor live portfolio valuations, and analyze asset allocation using up-to-date market data. Every transaction is recorded, making the trading process transparent, traceable, and easy to audit. For this project, our goal was to build the core features of the application, including portfolio and transaction management, key portfolio metrics, add and remove operations, and complete backend integration. Ultimately, we aimed to deliver a reliable product with a smooth user experience, stable APIs, and synchronized market data that is robust enough for a live demonstration and stakeholder evaluation.

acceptors · architecture
This diagram shows the architecture of our system. At the top, we have the main user request path. The React frontend sends an HTTP request to the Spring Boot backend. The backend checks the request and then reads or updates data in MySQL. After that, the result is sent back to the frontend. At the bottom, we have a separate background worker. The worker regularly gets the latest prices from an external market data API. It then saves the new prices to the database. We separated these two paths because external APIs can sometimes be slow. Users do not need to wait for a market data request every time they use the system. We also use a CI pipeline to test our changes. This architecture makes the system easier to test, maintain, and extend.

Design Logic

Application Focus: Typed UI + structured APIs reduce ambiguity across layers. Data Discipline: Persistent records and migrations make the system explainable. Operational Confidence: Documentation and CI checks support repeatable delivery.

Takeaway

Our stack choices were driven by maintainability, observability, and stable product behavior rather than novelty. We prioritized reliable delivery over technical variety.

acceptors · technology
Finally, this slide shows our main technology choices. For the frontend, we use React, TypeScript, and Vite. They help us build the interface quickly and keep the code clear. For the backend, we use Java 21 and Spring Boot. They provide stable REST APIs and support our business logic. We use MySQL 8 to store portfolio data, trades, holdings, and market prices. We also use scheduled worker jobs to update market data in the background. For quality control, we use CI tests and API documentation. These tools help us find problems earlier. They also help different team members follow the same API rules. Overall, we chose this technology stack because it is reliable and easy to maintain.

Conclusion

What We Achieved and What We Learned

Delivered Outcomes

  • Portfolio lifecycle workflow implemented end-to-end.
  • Market synchronization and valuation integrated.
  • Demonstrable user-facing analytics dashboard.

Challenges We Faced

  • Cross-layer integration timing and contract drift risk.
  • Environment consistency in non-container startup paths.
  • Balancing rapid iteration with reliability safeguards.

Team Reflection

We collaborated effectively through ownership clarity, shared checkpoints, and disciplined integration feedback loops.

What We Would Do Differently

Introduce stricter contract tests earlier and establish environment templates at the very beginning of development.

acceptors · conclusion
Let's reflect on what we delivered and what we learned. We implemented the full portfolio lifecycle end to end — trades, positions, valuations, all connected. Market sync is live, and the dashboard reflects real pricing. Everything is demo-ready. The biggest challenge was cross-layer integration — keeping frontend, API, and worker aligned as we built independently. Environment consistency also took more effort than expected. What made us effective was clear ownership. Each member owned a module, decisions were fast, and shared checkpoints kept us integrated. If we did this again — stricter contract tests, and shared environment templates from day one.
